# RFC-001: Evaluation of CRDT vs JSON Patch Architecture

- **Status**: Decided
- **Decision**: Out-of-scope for v1.0 Core; tracked as post-v1.0 optional plugin (`@syncraft-labs/crdt-adapter`)
- **Author**: Denis Listiadi
- **Created**: 2026-09-09
- **Target Version**: v1.0+ (Post-v1.0 Plugin)
- **Related Issues**: #18

---

## 1. Context & Motivation

Syncraft Labs previously listed `"crdt"` in the package keywords of `@syncraft-labs/core`. However, the engine's internal synchronization architecture is built entirely upon **JSON Patches (RFC 6902)** generated by Immer-style proxy traps, combined with an outbox queue and compaction pipeline.

This gap between package metadata and actual implementation generated user confusion regarding whether Syncraft Labs is a Conflict-free Replicated Data Type (CRDT) library (such as Yjs or Automerge).

This RFC evaluates:
1. Whether Syncraft Labs should adopt a native CRDT backend in core.
2. The trade-offs of CRDTs vs JSON Patches + Pluggable 3-Way Merge for client-side state synchronization.
3. The roadmap and architectural design for optional CRDT integration post-v1.0.

---

## 2. Technical Evaluation of Alternatives

| Dimension | JSON Patches + Outbox (Current) | Native CRDT Core (Yjs / Automerge) | Hybrid Plugin Architecture |
| :--- | :--- | :--- | :--- |
| **Primary Paradigm** | Operation-based (RFC 6902 delta patches) | State/Operation-based Replicated Data Types | JSON Patches as primary; CRDT adapter as optional package |
| **Bundle Size Overhead** | **~3 KB** (zero external dependencies) | **+50 KB to +80 KB** (Yjs/Automerge wasm/core) | **~3 KB core** (+0 KB for default users) |
| **State Representation** | Plain JavaScript objects, Maps, Sets | CRDT structures (`Y.Doc`, `Y.Map`, `Automerge.Doc`) | Plain JS objects with adapter translation |
| **Compaction Efficiency** | High (O(N) single-pass last-write compaction) | Built into CRDT garbage collection (complex tombstone handling) | Standard compaction for JSON patches |
| **Conflict Resolution** | Pluggable: Last-Write-Wins & 3-Way Merge | Mathematical strong eventual consistency (SEC) | Configurable per store |
| **Migration Cost** | Zero (Current architecture) | Massive (Complete rewrite of proxy produce engine) | Low (Additive adapter layer) |

---

## 3. Decision Rationale

### Why CRDT is Out-of-Scope for Core v1.0

1. **Lightweight Core Positioning**: Syncraft Labs is designed as a lightweight, zero-friction local-first synchronization library with minimal bundle overhead (~3KB). Bundling heavy CRDT runtimes directly into core contradicts this design goal.
2. **Mental Model Simplicity**: Developers interact with Syncraft Labs using standard mutable draft syntax (`draft.user.name = "Alice"`), persisting standard JSON structures directly to IndexedDB. CRDT abstractions introduce proprietary data structures and complex tombstone lifecycle management.
3. **Pluggable Conflict Resolution Sufficiency**: The pluggable conflict resolution engine introduced in #17 (`conflictStrategy: "lastWriteWins" | "custom"`) fulfills >90% of real-world local-first application needs, including field-level 3-way merging and server push reconciliation.
4. **Keyword Accuracy**: The keyword `"crdt"` has been removed from `packages/core/package.json` to maintain accurate and trustworthy package metadata.

---

## 4. Post-v1.0 Roadmap: Optional CRDT Adapter

For collaborative real-time text editing and multi-peer peer-to-peer (P2P) topologies requiring strong eventual consistency, Syncraft Labs will introduce an optional external adapter package post-v1.0:

```
@syncraft-labs/crdt-adapter
  ├── YjsAdapter (Bridge between SyncStore and Y.Doc)
  └── AutomergeAdapter (Bridge between SyncStore and Automerge)
```

### Proposed Plugin Architecture

```ts
import { createSyncStore } from "@syncraft-labs/core";
import { createYjsAdapter } from "@syncraft-labs/crdt-adapter";

const yjs = createYjsAdapter({ room: "document-42" });

const store = createSyncStore<DocState>({
  storageKey: "doc-42",
  conflictStrategy: "custom",
  resolver: yjs.mergeResolver,
  pusher: yjs.pusher,
});
```

This ensures that users who do not require CRDTs pay zero bundle size and complexity tax, while users with collaborative text editing requirements can opt-in via a dedicated adapter.
